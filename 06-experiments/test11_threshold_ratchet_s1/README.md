# Test 11 — S1 threshold-ratchet and S2 planar-tile rejection screen

**Decision (this test): neither S1 nor S2 is rejected on timing or passive
density, but both fail on the *central* discriminator — writing/refreshing the
selective medium — and S1 additionally fails a worst-case release-force gate.
S1 is downgraded to "revive only with a banked/sub-stroked lift"; S2 stays
alive **only** in its double-buffered, off-line-written form. No physical
measurement has been made; all results below are arithmetic geometry.**

This experiment does not build a machine. It answers the cheapest rejection
questions from [Q1/Q2/Q5/Q7/Q8](../../05-research-questions/) before CAD or BOM
work, and records which claimed S1/S2 properties survive hostile arithmetic.

## Reproduce

Python 3.11+, standard library only:

```bash
python geometry.py        # pitch budget and mask geometry
python timing.py          # full-map and regional timing, every term explicit
python rejection.py       # A–H PASS/FAIL/UNCERTAIN table
python sensitivity.py     # break-even values: what would have to be true
python checks.py          # regression tests locking the reasoning
python build_coupon.py    # emits params.json + manifest.json + coupon.scad + STLs
python coupon_checks.py   # coupon pitch-budget + STL structural tests
```

Optional rendering with OpenSCAD 2021.01 is a separate, non-required step and is
**not** fabrication or physical validation. `build_coupon.py` additionally emits
slicer-ready binary STLs directly from axis-aligned box geometry, so no CAD
kernel or OpenSCAD install is required to obtain a printable object.

## Cheapest rejection test (the coupon)

The coupon is the smallest physical object that can reject S1: **5×3 cells at
the true 5.08 mm pitch**, five 10 mm rack pockets per column, a printable
cantilever pawl, a sliding threshold gate, and a threshold plate with a boss over
each armed cell. One common 10 mm broadcast stroke.

**Printable parts** (all generated by `build_coupon.py`; PLA, 0.4 mm nozzle):

| STL | What it is | bbox (mm) | volume (cm³) |
|---|---|---|---|
| `coupon_frame.stl` | base + guide sleeves + pawl roots + gate slots + plate end-rails | 25.9 × 18.2 × 48.4 | 7.25 |
| `coupon_column.stl` | visible cap + racked body (print 15 for the 5×3 array) | 4.72 × 4.72 × 44.0 | 0.64 |
| `coupon_pawl.stl` | rooted flat cantilever with wedge toe | 0.8 × 7.0 × 1.6 | 0.007 |
| `coupon_gate.stl` | vertical gate bar (2 walls) | 0.8 × 2.4 × 3.0 | 0.006 |
| `coupon_threshold_plate.stl` | horizontal bar + bosses over armed cells | 25.4 × 1.2 × 2.2 | 0.054 |
| `coupon_assembly.stl` | full assembly for viewing only (not a print) | 27.8 × 20.1 × 49.4 | 7.95 |

### Why the first coupon was not printable (hostile review, campaign DND-8)

The first `coupon.scad` was CAD *source* only and could not be printed or tested
as drawn. Defects found before any STL was issued:

1. **Floating threshold plate.** `plate_t = 0.30 mm`, placed at `z = col_h + 0.2`
   (44.2 mm) with no support and no attachment — unprintable (no bed contact)
   and mechanically meaningless.
2. **Unrooted pawl.** The pawl was translated to a Z but never joined to a
   load-bearing frame, so its release force was undefined.
3. **Decorative selection.** Nothing connected the threshold plate to the gate,
   so "the plate arms the cell" was not a mechanism.
4. **Sub-nozzle features.** 0.30 mm plate and 0.50 mm gate are below a reliable
   single-wall FDM trace on a 0.4 mm nozzle.
5. **No STL** existed at all.

### The pitch budget does not close for side-by-side pawl + gate

The most important correction is arithmetic, not cosmetic. Putting the pawl and
the gate bar **side by side in X** beside a printable column body does not fit in
5.08 mm:

```
body + pawl + bleed + gate + bleed  =  3.60 + 0.80 + 0.20 + 0.80 + 0.20 = 5.60 mm  > 5.08
```

The first coupon silently hid this by drawing pawl and gate in different modules.
**Fix:** stack the gate bar **above** the pawl in Z, in the same X/Y lane. The X
axis then only has to fit the pawl, and the budget closes:

```
body 3.60 + lane 1.48 (pawl 0.80 + clearance 0.20 + rail 0.48) = 5.08 mm
```

Rack pocket 2.40 W × 1.20 D on the 3.60 mm body leaves 0.60 mm side rails and a
2.40 mm web — all ≥ the 0.40 mm FDM minimum. `make_manifest()` asserts this and
`coupon_checks.py` locks it.

### Physical print plan

- **Printer/material:** Bambu Lab X1 Carbon, 0.4 mm hardened nozzle, PLA. These
  are static-deflection parts; PLA is adequate for the short coupon campaign.
- **Orientation:** all parts print flat on the bed as authored (frame grows up,
  column grows up as a 44 mm tall prism, pawl prints flat in the X–Y plane).
  No supports required. The 44 mm column is a straight extrusion, so it needs no
  support; expected corner bulge is measured, not assumed (see gate below).
- **Layer height:** 0.2 mm, 3 walls, 25% infill for the frame; 100% for pawl and
  gate (thin parts).
- **What each measurement closes:**

  | Measurement | Assumption it retires |
  |---|---|
  | Column fits/ slides in sleeve with 0.20 mm bleed, 20 cycles | printed clearance is achievable at 5.08 pitch |
  | Pawl release force, 10 copies, static spring gauge | release-force spread sd ≤ 9% of mean (Test D break-even) |
  | Gate travel fully clears the pawl over 100 cycles | broadcast decode has zero missed/double steps |
  | Column holds 1 N load 1 h with no creep > 0.2 mm | passive PLA load path survives a miniature |

- **Biggest single unproven assumption the coupon retires:**
  **printed release-force variation across many identical pawls.** Every
  arithmetic PASS in this folder depends on the per-part release force sitting
  inside a window that (from `sensitivity.py`) collapses at ≈ 9% force sd. No
  number in this folder measures that sd; 10 printed copies and a spring gauge do.
  If the sd exceeds 9%, S1's shared broadcast stroke cannot be trusted and the
  variant type must change regardless of how well the geometry fits.

Measurable pass/fail gates for the printed coupon:

| Gate | Threshold | If failed |
|---|---|---|
| Missed / double steps over 100 cycles | 0 errors | S1 broadcast decode is unreliable |
| Loaded neighbor release (1 N on neighbor) | < 0.2 mm motion | Regional isolation claim dies |
| Pawl release force spread across 10 copies | sd ≤ 9% of mean | 6400-part board cannot be trusted |
| Idle holding under 1 N | no state change, no creep > 0.2 mm/1 h | Passive load path dies |
| Gate selection force window | exists and ≥ 2× margin | Print-process variation dominates |

If any gate fails, do **not** proceed to a 10×10 tile or a full mask writer.

## Results (arithmetic only)

### S1 — broadcast threshold ratchet

| Test | Verdict | Number |
|---|---|---|
| A sub-surface gate+pawl density | PASS | 2.28 mm available vs 1.10 mm needed beside a 2.0 mm shaft; visible top gap is only 0.36 mm |
| A2 rack pocket side rail | PASS | 1.76 mm rail on a 4.72 mm face |
| B aggregate stroke force | PASS (marginal) | ~1,441 N board-wide at 0.225 N/cell, cap 1,500 N |
| B2 all-cells-armed worst-case stroke | **FAIL** | 2,368 N if all 6,400 pawls release in one stroke; break-even 0.234 N/cell |
| C mask write inside visible 30 s | **FAIL** | 12,800 hole/set ops: serial 2,560 s, 80-channel 56 s |
| C2 off-line writer vs re-plan interval | PASS | 56 s to write a full board off-line vs a 5 min interval |
| D print-force variation window | PASS at 5% sd, **FAIL** at 10% | break-even sd ≈ 9.0% of mean |
| E serial cell-service rate | PASS by construction | four broadcast strokes, not 6,400 services |
| F regional isolation (assumed frame stiffness) | PASS but UNVERIFIED | depends on an unknown frame stiffness; must be measured |

**S1 interpretation.** Decoding is timing-safe and the passive density fits, so
the "gate cannot fit at 5.08 mm" worry is **not** the killer. The killers are:

1. **Worst-case release force (B2).** A map that arms most cells in one stroke
   needs ~2.4 kN at 0.37 N/pawl. Fixable only by *banking* the board (e.g. 8
   banks of 800 cells, four sub-strokes each) or by making each pawl release
   below ~0.23 N. Both are design changes, not parameters.
2. **Mask programming (C).** Four unary 6,400-bit planes are 12,800 decisions.
   Nothing inside the visible transition can write them; they must be
   pre-written. That converts S1's real cost into planar media + registration,
   i.e. **S1 collapses into S2** unless disposable media are acceptable.

### S2 — swappable planar-memory tiles

| Test | Verdict | Number |
|---|---|---|
| Full-map read timing (shared lift) | PASS | ~2.0 s to lift, settle and verify all tiles |
| Regional read timing (one tile) | PASS | ~1.8 s per tile (excludes off-line writer time) |
| C2 off-line writer | PASS | 56 s to prepare the next board off-line |
| G media-stack misalignment vs hole clearance | PASS | √4 × 0.10 = 0.20 mm stack vs 0.40 mm one-sided clearance |
| H follower taper capture | PASS | 6.93 mm capture vs 0.20 mm accumulated error |

**S2 interpretation.** S2 survives the arithmetic because it moves the entire
hard problem into an **off-board writer** and **double buffering**. That is a
legitimate systems answer, but it is *conditional* on two unproven product
properties that arithmetic cannot settle:

- **Surprise maps.** If the next map is not known ~1 minute ahead, the writer is
  the bottleneck and the 30 s visible budget is irrelevant.
- **Exchange disturbance.** Replacing a tile's medium while a miniature stands on
  a neighbor is exactly the [Q5](../) regional-isolation protocol, which no
  number above can validate. Test F/`regional_isolation` shows the *arithmetic*
  can pass; the *physical* frame stiffness is an unknown input.

## What this changes in the repository

- S1 is **not** killed on density; it is killed on programming and worst-case
  release force. Update the [S1 candidate](../../04-architecture-candidates/)
  accordingly.
- S2's advantage is confirmed to be *system-level* (pipelining), not mechanical.
  It should be pursued as **pre-planned / double-buffered**, with surprise maps
  treated as a separate, weaker mode.
- The single experiment that most cheaply discriminates S1, S2 and S4 is still
  the [Q5](../../05-research-questions/) regional-isolation rig with a loaded
  untouched tile. Build that before any 10×10 tile.

## Evidence level

| Evidence | What was established | What was not |
|---|---|---|
| Analytic geometry (`geometry.py`, `build_coupon.py`) | Pitch budget, hole/rail/clearance arithmetic | Printed feature quality, friction, wear |
| Force/timing models (`timing.py`, `rejection.py`, `sensitivity.py`) | Break-even force, sd and channel counts; every timing term explicit | Loaded motor ability, real damped stroke time |
| Regression tests (`checks.py`) | The stated reasoning is reproducible and deterministic | Any physical property |
| Coupon STL/SCAD (`build_coupon.py`, `coupon_*.stl`) | A dimensionally exact, self-supporting, slicer-ready object at true 5.08 mm pitch; pitch budget closes with printable walls | Print quality, assembly fit, friction, wear, measured force |
| Coupon tests (`coupon_checks.py`) | STL headers/counts, no degenerate triangles, nonzero extents, pitch budget asserted | Whether the print behaves as drawn |

**Manifold caveat (honest):** the STLs are emitted as unions of axis-aligned
boxes. Where two boxes of the *same* part touch face-to-face the mesh is not
strictly edge-manifold (`trimesh.is_watertight` is `False` for `frame`, `pawl`,
`assembly`; `True` for `column`, `gate`, `plate`). This is expected for a box
union without CSG and is handled correctly by slicers (even-odd fill / non-manifold
repair). The coupon checks therefore assert *slicer-relevant* properties, not
strict manifoldness. Do not read "printed evidence" into any of this.

No claim in this folder is physical validation.
