# Instructions for Codex and one-off contributors

This is an **owner-directed project**, not an autonomous Paperclip laboratory. Do the requested task; do not self-start research campaigns, issue chains, routine audits, agent handoffs, or status-only commits. Every substantive task should answer a concrete question, have a useful deliverable and a stop condition. Optimize decisions per token, filament and owner time.

**Current priority:** prove a simple mechanism that moves multiple pins **up and down independently without mechanically disturbing neighboring pins**. Preserve D&D usability: **one-inch (25.4-mm) squares, thin walls along square boundaries and room for miniature bases**. Optical height readback, minor drift correction and elaborate automatic homing/recovery are later-stage work, not current research priorities. Always preserve basic physical safety.

For substantial design work, read the [mission](01-project-description/shape-display-mission.md), [current priorities](02-design-criteria/current-prototype-priorities.md), and only the *relevant* other criteria in `02-design-criteria/`. Do not load hundreds of experiments or the full idea log by default.

Repository organization: `01-project-description/owner-ideas.md` is historical brainstorming, not an automatic task list. `03-engineering-knowledge/` holds reusable principles; `04-architecture-candidates/` candidate designs; `05-research-questions/` open questions; `06-experiments/` measured/computational evidence and source; `07-evidence-and-decisions/` decisions; `08-integrated-designs/` full design packages. Consult only material relevant to your assigned task.

Challenge high-precision components replicated thousands of times. Consider shared actuation/selection where it truly simplifies the *complete* mechanism, with honest force, support, build time, cost, assembly and repair. Screen cheaply before deep local optimization. A simulation can reject a design but is not a physical pass. Explicitly distinguish assumptions, calculations, CAD, slicer outputs, owner-reported hands-on observations and measurements; preserve negative evidence and provenance.

Keep changes focused; do not rewrite historical experiments for style. Use existing ID-bearing conventions for substantive new research, but don't invent new experiment files for documentation edits. `./repo help` / `./repo check` are available when ID/structure work needs them; `./worktree help` is optional for local parallel work. No hard-coded machine paths or mandatory Paperclip process. Run pertinent checks and state clearly if they could not be run.

If explicitly tasked with owner printing, follow `owner-print-tests/AGENTS.md`, supply **Bambu Studio `.3mf` projects for the Bambu Lab X1 Carbon with verified printer, filament and process settings saved in the file** (STLs may remain as optional geometry sources) and keep tests tiny. Sander may print much later or never; don't block on it. No unrequested purchases, account changes or follow-on tasks. **Stop at the requested deliverable.**
