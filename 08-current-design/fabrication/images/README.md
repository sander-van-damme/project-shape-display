# S5-R fabrication renders (DND-69 / DND-88)

Board-viewable PNG renders of the **S5-R** printable part set, the assembled
per-cell register, and the **whole machine assembled**. Generated by
[`../tools/render_images.py`](../tools/render_images.py) and
[`../tools/render_machine.py`](../tools/render_machine.py) from the committed
OpenSCAD-produced STLs in [`../stl/`](../stl/).

**Evidence class: CAD render of the committed OpenSCAD meshes. NOT a print and
NOT a measurement** ([DND-27](/DND/issues/DND-27)). These images visualise
geometry; they validate nothing physical. No part has been printed and none
will be — the board performs the first physical print.

## Full machine assembled (DND-88)

The **whole S5-R machine** composed from the committed part STLs at their real
assembly offsets: the **3 × 3 cartridge field** (411.48 × 411.48 mm = the real
81 × 81 cell envelope; 80 × 80 = 6,400 used), the **3 × 3 platen lift deck**
under it, the perimeter **lift-frame rails** and corner **guide brackets**, three
witness **rack strips + sourced steel rods**, the **bank drive housing** (−X edge)
and the **writer carriage** (+X edge).

The installed register (rotor + pawl + keeper + detent) is shown in a
**representative 9 × 9 sub-block = 81 of the 6,400 cells** — the full 6,400
installed cells are *not* individually modelled (that would be ~25,600 tiny
solids) and the label on every image says so.

## Reproduce

```sh
pip install numpy pillow
python 08-current-design/fabrication/tools/render_images.py         # parts + register -> images/
python 08-current-design/fabrication/tools/render_images.py --check # verify
python 08-current-design/fabrication/tools/render_machine.py        # full machine -> images/
python 08-current-design/fabrication/tools/render_machine.py --check # verify
```

Each part image filename is `<part>_<view>.png` (`iso` / `front` / `top`); the
machine images are `assembly_full_machine_<view>.png`,
`assembly_full_machine_exploded_<view>.png` and
`assembly_register_9x9_<view>.png`. The machine-readable records are
[`../manifests/render_images_record.json`](../manifests/render_images_record.json)
and [`../manifests/render_machine_record.json`](../manifests/render_machine_record.json).

## How these renders are made (and why not OpenSCAD's PNG backend)

The committed `stl/*.stl` are produced by **real OpenSCAD**
([`render_fab_parts.py`](../tools/render_fab_parts.py)) and every PNG here is
rasterized from **those exact meshes**, so the images are true to the shipped
geometry.

OpenSCAD's *own* PNG backend needs an OpenGL context. In the agent container
there is no display and no GPU (the offscreen Qt platform reports
`Can't create OffscreenView: Unable to obtain GL Context`), so OpenSCAD can
render STL but cannot rasterize a PNG. `render_images.py` therefore rasterizes
the OpenSCAD meshes with a small software renderer (numpy + Pillow): z-buffered,
flat-Lambert shaded, deterministic camera. It needs no GL, no X and no OpenSCAD.
